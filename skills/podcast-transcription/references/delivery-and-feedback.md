# Delivery, readback and feedback

A request for more context continues the existing question; it does not answer
it. Keep the original suggestion open while supplying the requested audio or
explanation, so a later reply or thumbs-up on that suggestion still resolves it.
Use the project's explicit text-reply classification helper after reading the
meaning of the authenticated reply. Receipt alone must not permit publication.
Keep earlier replies and send receipts for replay protection; do not repeat the
question or report an ordinary context request as a production failure.

## Native captions

Human corrections can arrive after native publication or in another chat. Fetch
the current native transcript/hash before making video derivatives; preserve an
opening joke or pun as deliberately corrected rather than replacing it with an
ASR guess. Track each accepted correction across the reviewed word/cue text,
native VTT/JSON/page, burned-in video and YouTube caption track. Do not claim the
video is corrected merely because its companion VTT changed. Text-only corrections
can preserve cue times when audio has not changed; keep raw recognition immutable.

The publishing skill owns installed Castopod behavior, helper commands and the parser
compatibility derivative. Read its native-transcript operations reference before attachment;
valid WebVTT alone does not guarantee correct installed-parser output. Current known parser
limitations include numbered cues, multiline payloads and literal closing voice tags. Recheck
on upgrades instead of treating those limitations as permanent WebVTT requirements.

Bind the reviewed final VTT to the exact served audio and existing episode GUID. Before and
after the authorized attachment, compare editorial fields, publication date, audio identity,
notes and unrelated media. Check every parsed cue's wording, start/end and speaker, public VTT
checksum/MIME, JSON companion, rendered page paragraphs and the exact RSS item's transcript
URL/type/rel. Paragraph count and content matter: all words can still render as one block.

A contemporaneous analytics counter can change during readback. Investigate an observed delta
against the current maintained code and this episode's window; do not reset it, infer exact
request causality, or carry an earlier episode's exception into a later verification. Preserve
the first failure observation and later authoritative readback without inventing a frozen
failure artifact or repeating a successful attachment.

Apple or Fountain catalog/page observations do not prove a player has loaded the supplied
transcript. Distinguish RSS delivery, supplied-transcript attribution and actual phone display/
seek behavior. Honor cancelled monitoring; a new transcript does not authorize a new schedule.

## Shared sample context

Phone and desktop agents do not automatically share chat history. Before sending, save the
question ID, episode/time, actual uncertainty, provisional interpretation if any, audio paths/
hashes, owner and the exact question in the project's shared feedback record. Read it afresh
when a reply or callback arrives. Keep routing/authentication material private and use the
existing transport's idempotent send/registration mechanism.

A useful message explains what to listen for. For each sample, send a voice memo and then its
own text question; do not send an unexplained clip bundle or infer context from a group title.
Do not ask whether a word was clipped using only an original recording: a join-quality question
needs a labelled, reviewed comparison. A PCM editorial illustration is not proof of an encoded
candidate's quality or decoding behavior.

Minor-question fallback applies only to the specifically sent minor question, after its real
deadline. It does not authorize publication of raw ASR. Serious content/quality choices remain
explicit decisions. Save exact late feedback, assess it against the recording and change only
the supported cue text/timing/attribution. Use the maintained transcript update/replacement
path, preserving unaffected cues and episode identity while avoiding duplicate attachments.
Revalidate affected parser/public outputs and the full cue set without recreating the episode. Keep old receipts as historical provenance, clearly identify the current version,
and avoid duplicate acknowledgements, resends or applying a correction twice.
